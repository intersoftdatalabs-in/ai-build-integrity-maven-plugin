# Feature: Resume-Safe Hash Regeneration (#27)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When resuming a failed multi-module Maven build with `-rf :module-name`, regenerate hashes for the resuming module so intentional edits are not flagged as tampering.

**Architecture:** Extend HashGeneratorMojo with a new parameter `resumeFromModule` that causes it to regenerate hashes for the specified module (and only that module) when resuming a build. HashVerifyMojo will detect this and skip verification for the resumed module's hashes, since they were just regenerated.

**Tech Stack:** Java 11, Maven Plugin API

---

## Problem Analysis

When a multi-module Maven build fails and is resumed using `-rf :module-name`:
1. Original hashes were generated before the failure
2. Files may have been intentionally modified during the failed build (e.g., pom.xml changes)
3. Verification fails because current file content doesn't match stored hash

The solution is to detect resume mode and regenerate hashes for the resuming module before verification runs.

// Detect if we're resuming a specific module via -rf
String resumedProject = session.getResumeFrom();
boolean isResumeBuild = resumedProject != null && !resumedProject.isEmpty();

if (isResumeBuild && resumeFromModule != null && !resumeFromModule.isEmpty()) {
    // Only regenerate hashes if this module matches the resume target
